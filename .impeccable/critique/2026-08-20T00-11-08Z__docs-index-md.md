## Design Specificity Verdict

**LLM assessment**: This is authored, not templated — brand green sampled from the real logo with documented AA-contrast math, a hero built around the real six-subcommand model, and CLI docs written with genuine domain fluency (SemiBin2 co-abundance, Flye contig rules, CheckM2 thresholds). The exception is the "Advanced" pages (HPC/Performance/Reproducibility) — correct but flat, generic prose sitting next to the highly-crafted homepage/installation/recover pages.

**Deterministic scan**: The bundled detector ran against a freshly-built site (`mkdocs build` succeeded cleanly, 0 warnings) in degraded/regex-fallback mode. It returned 30 findings: 15 files flagged for `em-dash-overuse`, 4 for `layout-transition`, 1 for `side-tab`, 3 for `overused-font`.

`em-dash-overuse` is confirmed a systemic false positive on this codebase — checked across all 15 flagged files, not a sample: several (`examples.md`, `faqs.md`, `installation.md`, `advanced/performance.md`) have **zero** actual em-dash characters despite being flagged with counts of 11–25, because this CLI-heavy site is saturated with `--flag-name` syntax that the regex fallback conflates with em-dashes. This rule category should be disregarded entirely for this repo until the detector's full HTML/CSS parser is available. `layout-transition` findings are inside MkDocs-Material's own bundled vendor CSS, not project code.

`side-tab` and `overused-font`, however, are **real, project-authored findings**, confirmed at `docs/stylesheets/extra.css` lines 30, 634, 923, and 933 (a left-border blockquote treatment and two `"Space Grotesk"` font-family declarations) — worth a look, though not urgent.

**Bug found and fixed during this critique**: Assessment B's browser-substitute check (grepping the actual built HTML) caught that the `!!! warning "Deprecated"` block I added to `usage/recover.md` in the previous round was indented 2 spaces to match its surrounding paragraph, which breaks Python-Markdown's admonition parser — it was rendering as raw literal `!!! warning "Deprecated"` text instead of a styled callout. Confirmed via direct inspection of the built HTML (`class="admonition warning"` was absent; raw markdown leaked through). Fixed by dedenting to column 0 and rebuilding to confirm it now renders as `<div class="admonition warning">`.

**Visual overlays**: Not available — no browser/screenshot tooling was exposed in this session. Assessment B substituted a deterministic grep-based check of the built HTML in place of screenshots, which is how the admonition rendering bug above was actually caught (a purely visual pass might have called this "probably fine").

## Overall Impression

The site's best writing — the homepage, installation, and the recover.md contig-rule table — is genuinely excellent, specific, and well-reasoned. But that same care hasn't reached the rest of the site evenly: admonitions exist in only 3 of ~38 pages, the highest-traffic content type (CLI reference pages, all ~400+ lines) has zero progressive disclosure despite the tooling for it already being configured and unused, and the site's one moment of real error-recovery empathy (`faqs.md`'s worked failure example) doesn't echo anywhere near the flags actually likely to cause that failure.

## What's Working

- `docs/faqs.md`'s worked Snakemake failure example (added last round) is the single best piece of UX writing on the site — concrete jobid/shell/log-path text instead of a hypothetical, giving a first-timer exactly what they'd panic-search for.
- `docs/usage/recover.md`'s Flye contig-inclusion table + worked example (also added last round) turns five interacting, easily-misused flags into something a reader can actually reason about with real numbers.
- `docs/stylesheets/extra.css`'s contrast math remains rigorous and documented — light-mode accent deepened to 4.93:1, dark-mode brand green verified at 8.35:1, with comments explaining why for nearly every rule.

## Priority Issues

**[P0] Admonitions are sparse and inconsistently applied to genuinely load-bearing content**
- **Why it matters**: Only 3 of ~38 markdown files use `!!!`/`???` blocks at all. `guides/hpc.md`, `advanced/performance.md`, and `advanced/reproducibility.md` — the newly-grouped "Advanced" section — have none, despite content like the `--unlock` corruption risk (currently plain prose in faqs.md) and the `--snakemake-cmds` trailing-space footgun (currently a plain blockquote in hpc.md, line 45). Once a reader has seen the warning pattern used correctly elsewhere, its absence elsewhere reads as "this part is safe" — which isn't true.
- **Fix**: Convert the `--unlock` corruption warning and the `hpc.md` trailing-space note to `!!! warning` blocks; audit all pages for equivalent risk language ("corrupt," "exceed," "cannot be undone") currently sitting in plain paragraphs.
- **Suggested command**: `/impeccable clarify`

**[P1] CLI reference pages have zero progressive disclosure despite the tooling already being configured**
- **Why it matters**: `usage/recover.md` is 400+ lines across 8 flat option groups; `pymdownx.details` is enabled in `mkdocs.yml` but never used to collapse anything. Cognitive-load checklist shows 5 of 8 failures concentrated in exactly this content type, which is also the highest-traffic pattern on the site (every CLI subcommand page follows it).
- **Fix**: Wrap secondary groups (QC options, Annotation/bin processing, Misc options) in collapsible `??? note` blocks, left open by default only for Input/Binning options.
- **Suggested command**: `/impeccable layout`

**[P2] No recovery guidance for the site's highest-stakes destructive action**
- **Why it matters**: `faqs.md` describes `--unlock` risk ("can allow concurrent processes to corrupt workflow state") but stops there — no way to tell if corruption occurred, no next step. This is Nielsen heuristic 3 (user control/freedom) failing at exactly the moment a user needs it most, mid-crisis after an interrupted HPC run.
- **Fix**: Add an "if this happens" subsection — how to tell if corruption occurred, whether a from-scratch rerun is required, which `.snakemake/` state to inspect — and cross-link `advanced/reproducibility.md`'s "Retain the run state" section, which already lists the right files but isn't referenced from here.
- **Suggested command**: `/impeccable harden`

**[P3] Three competing install paths with weak default steering**
- **Why it matters**: `installation.md` presents Bioconda, Pixi, and pip as equal-weight headings; the "pick one" guidance is a single sentence above the fold that a skimmer can miss, and pip's caveat (it doesn't provision the full external toolchain) is easy to read past. Jordan (new grad student) is exactly the persona this bites.
- **Fix**: Lead with a one-line decision guide ("Most users: Bioconda. Contributing to Aviary: Pixi. Already managing tool deps yourself: pip") as a small callout before the first install heading, not buried in prose.
- **Suggested command**: `/impeccable clarify`

## Persona Red Flags

**Jordan (First-Timer)**: `usage/recover.md`'s 400+ line, 8-group flag wall with no progressive disclosure is exactly the kind of page that causes a new grad student to bounce — nothing signals "you only need the first section." `guides/hpc.md` assumes familiarity with Snakemake profiles and PBS/`mqsub` conventions with zero link to `concepts.md`.

**Riley (Deliberate Stress Tester)**: The "output directory is locked after an interrupted run" entry in `faqs.md` is precisely the failure Riley would trigger deliberately (kill -9 mid-run) — the doc gives no verification step to confirm a safe unlock and no way to check for partial-write corruption. `--strict` (`recover.md`) silently changes failure semantics with no admonition flagging the tradeoff.

**Sam (Accessibility-dependent)**: Motion handling remains genuinely good (`prefers-reduced-motion` respected, contrast ratios documented and verified). Not fully auditable without browser tooling this round — worth a dedicated accessibility pass on `docs/overrides/main.html` to confirm it preserves Material's built-in landmarks and skip-links.
